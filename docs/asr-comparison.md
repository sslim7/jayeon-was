# 받아쓰기 품질 비교 — 서버 ASR vs 온디바이스 Whisper (2026-09-18)

## 왜 쟀나

통화 1건 원가 **105원 중 90원(85%)이 받아쓰기**다(→ `llms.md`). 공급자를 바꿔서는 한 푼도
못 아낀다는 것이 이미 확인됐으므로(알리바바가 최저가), 비용을 줄이는 길은 **받아쓰기를
폰에서 하는 것** 하나뿐이다. 그러면 서버는 분석만 하므로 **105원 → 13원**이 된다.

과거에 폰 받아쓰기를 시도했다가 「이 품질이면 쓸 수 없다」로 접은 적이 있다. 이 문서는
**그때의 실패가 Whisper 때문인지, 폰에 넣을 수 있었던 모델 크기 때문인지**를 가른다.

🔴 **핵심 전제가 바뀌었다.** 예전에는 787MB 안에 **받아쓰기 모델과 요약 모델을 둘 다** 넣어야
해서 받아쓰기 모델이 작을 수밖에 없었다. 지금은 요약을 서버가 하므로 **그 용량 전부를
받아쓰기에 줄 수 있다.** 이 비교는 그 전제 위에서만 의미가 있다.

---

## 방법

같은 상담 녹음 **1건**(28분 26초, 모노 48kHz, 한국어)을 세 가지로 받아쓰고, **분석은 셋 다
동일하게** `qwen3.7-plus` 로 돌렸다. 분석 모델·프롬프트가 같으므로 **차이는 받아쓰기에서만
온다.**

| 이름 | 받아쓴 주체 | 레코드 |
|---|---|---|
| 알리바바 | `qwen-audio-3.0-asr-flash-filetrans` (서버) | 「현정」 |
| 맥북 | whisper.cpp `large-v3-turbo` 1.6GB, M2 Pro, Metal GPU + 8스레드 | 「현정-맥북」 |
| 폰 | 예전 `whisper.rn` 소형 모델 (787MB 안에 요약 모델과 동거) | 「현정-모바일」 |

⚠️ **n=1 이다.** 아래 판단은 통화 한 건에서 나왔다. 특히 「어느 요약이 더 낫다」는 평가는
이 한 건의 성격에 좌우될 수 있다. 결론을 굳히려면 몇 건 더 필요하다.

## 1. 원문 비교

| | 알리바바 | 맥북 | 폰 |
|---|---|---|---|
| 글자 수 | 9,976 | 9,863 | 6,526 |
| 조각 수 | 264 | 318 | 314 |
| 화자 분리 | **O** (0/1) | X | X |

⚠️ **글자 수 차이를 「내용 누락」으로 읽으면 안 된다.** 처음에 폰이 34%를 놓쳤다고 판단했는데
**틀렸다.** 실제로 같은 구간을 나란히 놓고 보니 말은 전부 잡혀 있었고, 조각을 잘게 쪼개고
조사·어미를 흘려 글자 수가 준 것이었다. **숫자만 보고 품질을 판정하지 말 것.**

### 실제 차이는 고유명사와 단어 정확도다

같은 구간(0~25초, 180~215초)을 대조한 결과:

| 실제 | 알리바바 | 맥북 | 폰 |
|---|---|---|---|
| 여보세요? | 여보세요? | 여보세요? | **안녕하세요.** ✗ |
| 더메이(회사명) | 더메이 | 더메이 | **도매** ✗ |
| 아저씨 | 아저씨 | 아저씨 | **저시** ✗ |
| 마지노선 | 마지노선 | **맞으면 노선** ✗ | **마지막 노선** ✗ |
| 영현/영연(고객명) | 영연 | 영현 | 영현 |
| 권자연/권자현(팀장) | 권자현 | 권자연 | 권자연 |

- **폰**: 고유명사와 일반 단어를 모두 자주 틀린다. 회사명이 「도매」가 된 것이 치명적이다.
- **맥북**: 고유명사는 정확하고, 「마지노선」 같은 관용구를 놓치는 정도다.
- **알리바바**: 고유명사 정확. 다만 고객 이름을 「영연」으로 들었고 **맥북·폰은 「영현」으로
  들었다** — 2:1 이라 알리바바가 틀렸을 가능성이 있다. 팀장 이름도 세 모델이 갈렸다
  (권자현/권자연/권자연). **어느 쪽이 맞는지는 실제 이름을 아는 사람만 판정할 수 있다.**

## 2. 분석 결과 비교

| | 알리바바 | 맥북 | 폰 |
|---|---|---|---|
| **원가** | **93.5원** | **13.3원** | **12.5원** |
| ㄴ 받아쓰기 | 80.3원 | 0원 | 0원 |
| ㄴ 분석 | 13.2원 | 13.3원 | 12.5원 |
| 입력 토큰 | 13,967 | 14,573 | 12,999 |
| 상세 | 5건 | 3건 | 4건 |
| **할 일** | 1건 | 1건 | **0건** |

### 요약

**알리바바** — 담백하다. 「전체적으로 생각해 본 후 연락하기로 하고 통화를 마무리했다」.

**맥북** — 고객의 망설임과 다음 약속까지 잡았다. 「서비스 방식에 대해 **약간의 혼란을
표했으나**, **방문 상담을 통해 시뮬레이션 매칭을 받아보기로** 하고 전화를 마무리했습니다」.
상담 기록으로서 가장 쓸모 있다.

**폰** — 내용 파악은 멀쩡한데 **회사명이 「도매」로 굳었다.** 본문에 「**도매의가** 노블레스
등 타사와 달리」처럼 조사까지 붙어 문법이 깨졌다. 🔴 **LLM 이 문맥으로 고쳐 주지 않았다** —
원문에 「도매」로만 나오면 그대로 믿는다. 받아쓰기 오류는 분석 단계에서 회복되지 않는다.

### 🔴 「맥북이 전부 이겼다」가 아니다

셋이 **서로 다른 것을 잡았다.** 단순 우열로 읽으면 안 된다.

- **폰만 잡은 것**: 파티 예정일(9월 30일, 10월 15일, 10월 31일), 「음악 하는 사람들을 만나지
  말라는 **주변의 만류**」 — 상담 맥락상 의미 있는 정보다.
- **알리바바만 잡은 것**: 상세 5건으로 가장 촘촘하다. 파티 안내를 굳이 추천하지 않은 이유
  (11만 원 비용)까지 적었다.
- **맥북이 놓친 것**: 상세가 3건뿐이고 파티 세부가 얕다.
- **엇갈린 것**: 키 조건을 알리바바는 「본인 160cm」, 폰은 「본인 162cm」, 맥북은 「희망 상대
  175~176cm 이상」으로 적었다. 셋 다 통화에 나왔을 수 있어 **어느 쪽이 틀렸다고 단정할 수 없다.**

**갈라지는 지점은 두 개다**: ① 폰의 회사명 오류 ② 폰의 할 일 0건.

## 3. 결론

### 확인된 것

1. 🔴 **Whisper 계열로 충분한 품질이 나온다.** 맥북 `large-v3-turbo` 는 알리바바와 대등하고,
   요약은 오히려 더 쓸모 있었다. **과거의 실패는 Whisper 때문이 아니라 모델 크기 때문이다.**
2. 🔴 **받아쓰기 오류는 분석이 고쳐 주지 않는다.** 「도매」가 요약과 상세에 그대로 번졌다.
   원문 정확도가 결과 품질의 상한이다.
3. **화자 분리 없이도 분석이 됐다.** 맥북·폰 둘 다 화자 표시가 없는데 LLM 이 대화 흐름으로
   상담원과 고객을 갈라 요약했다. 화자 분리가 **필수는 아니다**(있으면 좋다)는 뜻이다 —
   이는 애초에 「타협 불가」로 잡았던 전제를 약화시킨다.
4. **폰 받아쓰기가 성립하면 원가가 105원 → 13원**이다. 실측으로 확인했다(위 표).

### 남은 미지수 — 🔴 이것이 결정한다

**폰에서 1.6GB 모델이 몇 분 걸리는가.** 맥북 1분 37초는 **Metal GPU + 8스레드** 숫자라 폰에
그대로 대입할 수 없다. 참고로 whisper.cpp `small`(162MB)을 **CPU 1스레드**로 돌리면 120초
오디오에 149초가 걸렸다 — 실시간보다 느리다.

측정 방법: 앱을 고칠 필요 없이 **폰에 모델 파일만 넣고 whisper.cpp 안드로이드 빌드로 한 번
돌려 보면** 된다.

### 다음에 볼 것

- **고유명사 프롬프트(initial_prompt / hotwords)** — 실패가 전부 고유명사였다. 회사명
  「더메이」와 상담사 이름은 **매번 나오는 고정값**이므로 미리 알려 줄 수 있다.
  **모델을 키우는 것보다 이쪽이 싸고 확실할 수 있다.**
- **양자화** — `large-v3-turbo` Q5/Q4 로 크기를 줄였을 때 한국어 품질 손실
- 앱 용량: 현재 134MB → 1.6GB 모델을 넣으면 1.7GB대가 된다. 오늘 기기 AI 모듈을 걷어내
  239MB → 134MB 로 줄인 것을 되돌리는 셈이다.

## 부록 — 재현 방법

이 비교는 운영 데이터에 레코드 두 개를 새로 만들어 수행했다(기존 레코드는 건드리지 않았다).

1. 맥북에서 받아쓰기: `whisper-cli -m ggml-large-v3-turbo.bin -f consult.wav -l ko -t 8 -oj`
2. `PUT /calls/{id}` (기기 업로드 경로)로 원문만 담은 레코드 생성 — 분석은 자리표시자로 둔다
3. `POST /calls/{id}/reanalyze` 로 서버 분석을 돌린다 (v0.1.6 이후: 작업 문서가 없어도
   레코드의 원문으로 만들어 이어간다)
4. 받아쓰기 원가가 0원으로 나오는 것이 정상이다 — 서버가 받아쓰기에 쓴 돈이 실제로 0이다

레코드: 「현정」(알리바바) · 「현정-맥북」 · 「현정-모바일」
